# Implementation status

An honest accounting of what's real/tested vs. scaffolded.

**Verified in this environment (Windows, no Docker):** full local stack — ML service,
Express API (SQLite + in-process queue), React frontend — run together and exercised
end-to-end over HTTP: video upload → `queued` → staged progress (`extracting_faces` → … →
`completed`) → analysis record with prediction, evidence, warnings → `features`, `signal`
(per-region waveform/spectrum arrays loaded from artifact files), `report`, `models`,
`visuals` (frame trace + stage timeline) and `videos/:id/stream` (Range) endpoints. The
test clip (`tests/fixtures/synthetic_face_video.mp4`, generated by
`scripts/make_test_video.py` with an injected 72 bpm pulse) was recovered at 75 bpm with
450/450 face detection; three pathological variants (no pulse, erratic BPM, desynced
regions) all came back `UNCERTAIN` with distinct warning profiles. The Analysis page's
`Pipeline` tab (live detection overlay, stage timeline, frame stats, window cards) was
verified in headless Chrome with zero console errors.

## Fully implemented and tested

- `services/ml/app/video/` — video I/O, metadata, validation
- `services/ml/app/face/` — MediaPipe Face Landmarker wrapper, ROI polygon extraction
  (forehead/left cheek/right cheek), tracking-quality bookkeeping
- `services/ml/app/rppg/` — Green, CHROM, POS extraction; detrend/normalise/band-pass
  filtering; sliding-window segmentation; SNR-based signal quality
- `services/ml/app/features/` — FFT/PSD BPM estimation, temporal stability, cross-region
  consistency, motion scoring, illumination scoring, feature vector assembly
- `services/ml/app/models/baseline.py` — classifier wrapper with transparent heuristic
  fallback (no trained model ships with this repo)
- `services/ml/app/explainability/` — evidence/warning generation, confidence calibration,
  report assembly; per-region waveform/spectrum artifacts saved to `storage/signals/{id}.json`;
  visualization trace (frame detections, stage timeline, windows) saved to
  `storage/visuals/{id}.json` on success **and** failure paths
- `services/ml/app/pipeline/` + `app/api/` — end-to-end orchestration and FastAPI wrapper,
  including the progress endpoint (`GET /v1/analyse/{id}/progress`, with stage `history`)
- `services/ml/tests/` — 15 pytest tests, verified passing (`node scripts/ml.mjs test`)
- `apps/api/` — Express + TypeScript: routes, controllers, services, **in-process analysis
  queue** (BullMQ/Redis removed), Socket.IO gateway, Prisma schema on **SQLite**, security
  middleware (upload validation, Zod request validation, centralised error handling);
  typecheck-clean
- `apps/web/` — React + Vite + TypeScript + Tailwind: routing, TanStack Query hooks,
  WebSocket hook, upload/player, ECharts visualisations, analysis progress UI, and the
  Analysis page tabs (Result / Pipeline with detection overlay, stage timeline, window
  segmentation); typecheck-clean and serving via `pnpm dev:web`
- `packages/shared-types/` — types shared between API and frontend (incl. `AnalysisRecord`)

## Written as complete source, not verified here

- Docker: `services/ml/Dockerfile`, `apps/api/Dockerfile` (migrate-on-boot),
  `apps/web/Dockerfile` (nginx proxying `/api` + `/socket.io`), `docker-compose.yml`
  (SQLite volume; Postgres/Redis/worker services removed) — **Docker is unavailable in this
  environment, so none of this has been executed.**
- `scripts/` — dataset preprocessing, feature extraction, baseline training (subject-grouped
  CV), deep-model scaffold (requires PyTorch + a real dataset), evaluation
- `GET /api/models` metrics (`experiments/results/evaluation_metrics.json`) — the file is
  produced only after running `scripts/evaluate.py`; until then the endpoint honestly reports
  `metrics: null`

## Not implemented (explicitly out of scope for this build)

- No trained classifier ships with this repo — no labelled real/fake dataset was provided.
  Every out-of-the-box prediction comes from the clearly-labelled heuristic fallback
  (`isHeuristicFallback: true`, `modelVersion: untrained-heuristic-v0`).
- No authentication/authorization implementation (Prisma has a `User` model; no auth routes
  were built — deferred past MVP in the spec).
- No deep-learning model is trained (`app/models/cnn1d.py` / `tcn.py` are architecture
  definitions only).
- No real-time/webcam analysis — `pages/LiveAnalysis.tsx` is an honest in-flight-analysis
  monitor; real webcam ingest is a labelled Phase 2 extension.
- No report PDF/HTML rendering (`report.service.ts` returns structured JSON only).
- WebSocket fan-out is single-process by design in zero-infra mode (queue lives in-process).

## First steps to actually run this

```bash
# 1. JS deps + SQLite
pnpm install
cp .env.example .env
pnpm exec prisma migrate dev --schema prisma/schema.prisma

# 2. ML service
cd services/ml
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
cd ../..
node scripts/ml.mjs dev

# 3. API + web (separate terminals)
pnpm dev:api
pnpm dev:web
```

Optional sample footage: `venv/Scripts/python scripts/make_test_video.py`.
